## Context

OLOS exposed the full Plan / Act / Observe domain catalogue to every team member. As teams grow (especially Regenerative Farm and Intentional Community projects) no one person owns all 16 domains, so the undifferentiated catalogue is noise — a livestock lead wades through finance, hydrology, and governance objectives to reach their three animal-husbandry objectives.

The fix is a **second, orthogonal role axis** layered on top of the existing system role:

| Layer | Controls | Home |
|---|---|---|
| **System role** (`ProjectRole`, pre-existing) | which *surfaces* a user can reach | `project_members.role` + `projectRoleCapabilities.ts` |
| **Operational role** (NEW) | which *domains* are a member's **default focus** within those surfaces | `project_members.operational_roles[]` |

Two pre-existing findings shaped the whole build and kept it cheap:
1. **The objective→domain resolver already existed** — `getObjectiveObserveDomains(objective): UniversalDomain[]` (already used by Plan search + the cyclical-review engine). So Plan/Act/Observe filtering needed **no catalogue re-authoring**. Because that mapping is coarse (per-stratum defaults + sparse per-objective overrides) and seed-scoped, the presentation rule is **never hide, only de-emphasize** — every out-of-scope item stays reachable.
2. **Act & Observe already navigate by `module = UniversalDomain` (16 domains)**, so the operational-role scope is naturally a `Set<UniversalDomain>` and the existing rails/bars are the filter hook points.

## Decision

Six built-in operational roles, stored **per-membership** (so they differ per project), that **stack** (union of domain scopes). The layer is **suppressed entirely on solo projects** and never applies to contractors / landowners / reviewers. Certain signals **always surface** regardless of filter. **Golden rule: never hide, only de-emphasize** — out-of-scope work dims or collapses but is always one glance/click away, and the always-surface engine promotes critical out-of-scope items back into focus.

**Scope axis = the 16 `UniversalDomain`s** (NOT the 7 `STEWARD_DOMAINS`, which stay as the s1-steward decision-rights capture). Role→domain map (`packages/shared/src/constants/collaboration/operationalRoles.ts`):

| Role | Domains |
|---|---|
| `ecology_soils` | land-base, climate, topography, hydrology, soil, ecology, monitoring-records |
| `food_production` | plants-food |
| `livestock` | animals-livestock |
| `infrastructure` | built-infrastructure, access-circulation, energy-resources, hydrology |
| `community_governance` | people-governance |
| `finance_legal` | economics-capacity, risk-compliance |

`hydrology` deliberately overlaps ecology_soils (natural water) + infrastructure (built water) — the **sole shared-resource domain**. `monitoring-records` is custodian-of-one for the *default view* but cross-cutting for *writes* (writes are governed by `PROJECT_ROLE_CAPABILITIES`, not this map). `vision-intent` is **primary-steward-only**, in no operational scope. Stacking the six roles yields all 16 domains minus `vision-intent`. **`[]` roles ⇒ full view** for everyone (safe degradation — the filter only engages when `scope.size > 0`; a misconfigured/empty role never produces an empty screen).

Owner persistence gap handled: the owner is implicit (`projects.owner_id`, no `project_members` row), so owner operational roles live in `projects.metadata.operationalRoles` (jsonb) and the members route synthesizes the owner row from it.

## Alternatives Considered

- **Re-author the objective catalogue with explicit per-objective domain ownership** — rejected: `getObjectiveObserveDomains` already exists; coarse mapping is mitigated by never-hide + always-surface + per-stratum counts + one-click Full view. A genuine mis-dim is a one-line override in one tested file.
- **Hard-filter (hide) out-of-scope work** — rejected as the founding decision: the mapping is coarse and seed-scoped, so hiding would lose real signal. Dim/collapse only.
- **Store operational roles on the user, not the membership** — rejected: roles differ per project; the membership row is the correct home (owner gap closed via `projects.metadata`).
- **Return a fresh `Set` from a Zustand selector** — rejected (Zustand v5 infinite-render trap): select the stable raw role array, memoize the Set.
- **Make `s1-steward-c9` a gating checklist item** — rejected: it must not change the steward objective's completion denominator or break progress/migration tests; non-gating like c7/c8.
- **Build focus-toggle + collapsible "Outside your focus" chrome on the legacy `stratum-spine` shell too** — rejected as out of proportion for a non-default opt-in surface; the legacy column dims in place and the LIVE shell carries the full chrome. Revisit only if `stratum-spine` is ever re-promoted.
- **Per-project role rename/extend (ADR Option C) + project-type role variants** — the rename + re-scope half **shipped 2026-06-28** (see *Update (2026-06-28)*); the override rides `projects.metadata` so no migration/enum/CHECK change was needed. Net-new custom roles + project-type default sets stay deferred.

## Consequences

- An assigned member now sees Plan/Act/Observe default-scoped to their domains, with a Full-view toggle and always-on critical signals; a solo project is byte-identical to before; `[]`-role members get the full view.
- The shared `apps/web/src/v3/roles/` module + the `scopeState`/`surfaceChip`/`roleBadges` visual contract on both objective cards (`ActTierObjectiveCard` + legacy `strata/ObjectiveCard`) are the reusable hook points for any future scoped surface.
- `getObjectiveObserveDomains` is now load-bearing for the default view (was Plan-search + cyclical-review only); a mis-dim is a single override line.
- The layer adds a second orthogonal axis to the collaboration model — system role (surfaces) × operational role (domains) — with the persistence seam (`resolveOperationalRoles`) ready for per-project customization.

## Update (2026-06-29) — pre-push review fixes

Before requesting push authorization, the six Option-C commits went through an exhaustive adversarial pre-push review (dimension reviewers → 3-skeptic verification → synthesis). It returned **NO-GO with 4 confirmed findings (0 refuted)** — three were wiring bugs sharing one root cause (the async resolver `useResolvedOperationalRoles` consumed as if synchronous), one was a coverage gap. All fixed TDD (both regression tests written **red-first**, watched fail, then green) and committed LOCAL as `4a5502ac` on `fix/operational-role-layer`; **still unpushed**.

- **BLOCKER — editor silently clobbered stored overrides.** `OperationalRoleEditor` seeded its drafts from a **lazy `useState` initializer**. But `useResolvedOperationalRoles` is a React-Query adapter: while `useProject` is pending it returns the BUILT-INS, then re-renders with the project's stored overrides. The lazy snapshot captured the built-ins before the query resolved and never re-seeded, so an **unmodified Save diffed built-ins against built-ins → `[]` → silently overwrote the project's stored `operationalRoleDefs`** — a direct violation of this ADR's lossless-round-trip guarantee. Fix: added `isLoading` to the resolver bundle (the pure core returns `false`; the hook folds in live query state via a second `useMemo` so the Set-bearing `domainsMap` keeps a stable identity), a re-seed `useEffect` keyed on `overridesSig = JSON.stringify(overrides ?? null)` + a `useRef` seed-guard (fires on the load→overrides transition and after a save refetch, **never** on the user's own draft edits), and an `if (isLoading) return null;` gate beside the admin/solo gate so neither render nor Save can run on the placeholders.
- **MAJOR — `MembersTab` roster chips ignored a rename.** The chips read the static `OPERATIONAL_ROLE_DEFS[slug].label`, so a project rename set in the editor mounted at the *top of that very tab* never reached the member chips below. Fix: resolve the chip label through `useResolvedOperationalRoles(projectId).labelFor(slug)`; the closed-enum stale-slug guard is kept.
